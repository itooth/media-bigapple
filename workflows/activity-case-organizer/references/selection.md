# 精选：从全部照片到活动页

目标：访客按顺序看完活动页，能还原这场活动怎么展开、谁以什么角色做了什么、产出了什么。张数是结果，不设固定上下限。去重只针对同一瞬间的重复，不能用来压缩张数。

## 1. 五遍法

1. **排序**：`archive.py scan` 按拍摄顺序编号，依据依次取 EXIF 时间 → `来源元数据.json` 里的时间 → 文件名时间戳 → 相机文件序号（如 `LIY_2661`）→ 文件名顺序，写在计划的 `orderSource`。下载在线相册时保留原文件名；改了名，就在输入目录写 `来源元数据.json`：`{"文件名": {"capturedAt": "ISO 时间", "originalName": "LIY_2661.JPG"}}`。
2. **看全部**：`curate.py sheets <计划> <输出目录>` 出编号拼图，每页 12 张，按拍摄顺序排，连拍候选组加同色框并标 `G编号`。每页都要看完。需要认人或读字（桌牌、投影、奖项名、屏幕内容）时，单独打开原图看。拼图看不清就停下重出，不准凭印象写。
3. **写描述**：每张都写 `review.evidence`，一句话说清画面里谁在做什么（≤40 字），例如「戴帽评委举手提问」「第三支路演队台上演示手机端」。这句描述是唯一真源：审阅页显示它，入选照片的文件名（也就是网站上的照片名称）直接用它，不另写一遍。人物身份只写看得出、有依据的（桌牌、屏幕、对方提供的材料），看不出就写外观或动作，不编名字。
4. **判连拍**：`similarGroups` 只是候选，组内只和拍摄顺序相邻的照片比较。逐组对照拼图，同一瞬间的重复只留信息最多的一张，其余标 `burst-alt` 并在 `representative` 写留下那张的 `sourcePath`；组里其实是不同瞬间（换了人、动作、屏幕内容），就给这组写 `keepAll` 理由。明显虚焦、闭眼、严重过曝或被遮挡的标 `reject-technical`，拿不准的留下。
5. **按覆盖精选**：每张填 `chapter`，能辨认的填 `subject`（谁、哪支队、哪个奖）。每个章节、每个主体至少选一张；同时控住节奏——有主体的章节，每个主体通常 1–2 张（如全景 + 特写、展示 + 问答）；没有主体的纯场景章节（签到、会场、打卡、合影等）通常 3–6 张，不要每换一个角度或一拨打卡合影就全选。确实需要明显超出时，在 `chapterNotes` 写理由。素材里没有的章节写进 `chapterNotes`，有主体但所有照片都不能用的写进 `subjectNotes`。

## 2. 活动类型与章节

助手按素材自己判断类型，在计划里写 `eventType` 和按时间顺序的 `chapters`，不用先问对方，覆盖表和审阅页会让对方看到并纠正。下表是起点，按实际流程增删：

| 类型 | 章节（按时间顺序） | 主体粒度 |
|---|---|---|
| 大赛、黑客松 | 签到入场、会场与主视觉、开幕致辞、评委与嘉宾、赛题规则、开发现场、工具与合作方、逐队路演、评委提问点评、颁奖、合影、细节花絮 | 每位致辞人、每位评委、每支路演队、每个奖项 |
| 大会、论坛、沙龙 | 签到、会场全景、开场、演讲、圆桌、观众互动、交流、合影 | 每位演讲人、每场圆桌 |
| 培训、工作坊、企业 FDE | 场地环境、讲解、学员实操、屏幕与成果、辅导交流、成果展示、合影 | 每个关键操作或成果 |
| 参访、交流 | 抵达、参观点、讲解、座谈、合影 | 每个参观点 |

我方在现场的角色（提供工具、担任评委等）以对方给的材料为准。有画面证据的必须入选；没有画面证据，覆盖表里写「素材中未见」，页面文字不替任何一方编造角色。

## 3. 每张照片的记录

写在整理计划的 entry 上：

| 字段 | 说明 |
|---|---|
| `review.evidence` | 必填，一句话描述，唯一真源 |
| `decision` | `selected` / `burst-alt` / `reject-technical` / `archive`；照片超过 30 张时每张必填 |
| `decidedBy` | `ai` 或 `user`。对方说的保留、恢复、去掉都记为 `user`，以后不得被 AI 改回 |
| `representative` | `burst-alt` 必填，留下那张的 `sourcePath` |
| `chapter`、`subject` | 章节必须在 `chapters` 里；主体看不出就留空 |
| `cover`、`homepage` | 封面最多一张；首页挑 3–5 张最能代表这场的 |

## 4. 命名与排序

写完 decision 后跑 `curate.py name <计划>`，不手工编分数：

- 入选：`01_活动照片/分数_[封面_][首页_]活动_<描述>.jpg`。封面 10000 分，之后按 `chapters` 的时间顺序分段递减，章节内按拍摄顺序，所以活动页从头看到尾就是活动经过。
- 未入选：`其他/相似连拍/`、`其他/技术淘汰/`、`其他/其余照片/`，文件名带审阅编号和描述。
- 描述里的 `_`、空格、斜杠等会替换成 `-`，意思不改。

之后照常 `archive.py apply`。对方审阅后改了取舍，就改计划里的 decision，再跑 `curate.py name` 和 `apply`，脚本会把文件挪到新位置，不会在相册里留下旧的一份。

## 5. 交给对方审的三件套

1. **全量审阅页**：`curate.py html <计划> <输出.html>`。全部照片按拍摄顺序排，带编号、章节、决定、描述、连拍组和代表照，可筛选、放大、翻页；本地双击就能打开，不依赖服务进程。对方说「把 166 加回来」，按编号改。
2. **覆盖表**：`curate.py coverage <计划>`，章节 × 主体，每格列入选编号，空格写原因，末尾附检查结果。
3. **精选活动页**：本地预览，网站原版式。

三件套一起交。来源是在线相册时，在 `03_社交媒体/` 加一条「完整相册」链接，方便参与者找到自己的照片。

## 6. 拦截与提醒

`archive.py apply` 和 `publish.py` 用同一套规则，出错就不往下走：

- 有照片没写描述，或描述超过 40 字
- 同一句描述用在 3 个以上的不同瞬间（同一连拍组内可以相同）
- 照片超过 30 张却没写 `chapters`，或有照片没写 decision
- 标了 `burst-alt` 却没写代表照，或代表照没有入选
- 有章节、有主体一张入选都没有，也没写原因

- 照片超过 100 张、入选比例低于 8% 或高于 35%，且计划顶层没写 `selectionNote` 说明原因

写了 `selectionNote` 后仍打印提醒但不拦。照片不超过 30 张的小活动不要求章节和覆盖，只要求逐张描述和连拍代表照。

## 7. 踩过的坑

- **441 张只选了 16 张**：AI 凭印象手写名单，其余 419 张写同一句理由。现在要求逐张描述、章节覆盖，拦截区间式描述。
- **相似算法把 307 张串成一组**：链式归组，A 像 B、B 像 C 就算一组，同一舞台背景下的签到、路演、颁奖全被串到一起。现在只在拍摄顺序相邻的照片里找，必须和组里每一张都像，每组最多 8 张。
- **拼图太小，认不出人**：每页 64 张时一格只有约 144px。现在每页固定 12 张；最差情况下，模型看图前把整页压到短边 768px，每格仍约 256px。认人读字另开原图。
- **下载相册时把文件名改成 ID**：拍摄顺序丢了。保留原文件名，或写 `来源元数据.json`。
- **只交精选页**：落选照片对方看不到，也捞不回来。现在三件套一起交。
