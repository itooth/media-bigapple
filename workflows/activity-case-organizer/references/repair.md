# 修旧活动

已经上线的活动直接在服务器的原始记录上改，不要求本地有归档：服务器记录 + 图床就是真源。每场一个工作目录，过程全部留档，回滚就是把 `before.json` 写回去。

建议工作目录：`素材库/.repair/<日期>_<活动目录名>/`。

```text
pull ─► 写修复单并请使用者确认 ─► apply ─► titles ─► posters ─► 看总览图、pick 换帧
  ─► upload ─► check ─► preview（使用者确认）─► push ─► audit 复查
```

```bash
R="python3 $SKILL/scripts/repair.py"; W=素材库/.repair/2026-11-17_某活动
$R pull 2026-10-28_某活动 $W        # 拉线上原样到 before.json / after.json，打印现有问题
# 写 $W/fixes.json（格式见 repair.py 顶部说明），给使用者看对照表，确认后：
$R apply $W                          # 挪作品视频、改简介，打印差异
$R titles $W                         # 视频标题去「活动视频_」前缀
$R posters $W                        # 缺封面的视频直接从图床地址取帧（不下载整段），出 总览N.jpg
$R pick $W <视频路径> <编号>          # 看总览图后换帧
$R upload $W --repo /网站工程         # 封面传图床、挂进记录
$R check $W                          # 同一套规则 + 和线上的差异
$R preview $W [更多工作目录] --repo /网站工程   # 本地预览：线上全部活动 + 这几场改后的
$R push $W                           # 线上仍等于 before.json 才写；写后读回核对
$R rollback $W                       # 需要时：撤回这次写入
```

## 修复单要使用者确认的部分

- **作品视频归哪个案例**：先出「视频 → 案例」对照表。作品视频默认各自成一个独立的视频案例，不并进同名的图片案例（使用者 2026-11-17 定的）；同一系列的多段（如口播·01–05）放进同一个视频案例。对不上、拿不准的问，不猜。
- **新案例的简介、改写的活动简介**：拟好给使用者改，≤15 字 / ≤20 字；原来的长文字放 `detail`（写进「## 详细说明」给 Agent 读），不丢。
- **活动视频**：现场拍的留在活动区，只补封面和标题。相似的现场片段全部保留（视频本来拍得少）。

## 封面

`posters` 在每段视频 8%–78% 处取 6 帧，自动挑最清晰的一张；旧数据里已有、网站没读的封面（视频条目的 `poster` 字段）直接沿用。总览图每张最多 9 段，绿框是自动选中。**必须逐张看总览图**：试点里自动选帧有约一成选到背影、糊帧、转场，用 `pick` 换。看不到图就重新出图，不准跳过。

网络断了重跑 `posters`，做过的会跳过。

## 写入的安全规则

- `push` 前会重新读线上，和 `before.json` 不一致就停：说明 pull 之后有人改过这场。重新 pull，把修复单再 apply 一遍。
- 写入后读回逐字核对，不一致立即报告。回滚：`$R rollback $W`，线上仍是这次写入的版本才会把 `before.json` 写回，避免覆盖别人后来的改动。
- 一次可以预览多场，但 push 一场一场来，每场读回通过再下一场。
- 改完跑一次 `audit.py`，确认这场的问题减少、全站没有新增。
