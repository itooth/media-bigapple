# 活动素材整理专家

一个入口贯穿归档、数据、预览和发布。沿用已有网站工程，UI 从统一数据渲染；更换版式不重新识别素材、不改活动 UID。整理规则、脚本和契约都在本 Skill，旧的三套整理 Skill 不再互相调用。

## 开始时

先看用户给的目录、已存 manifest/媒体映射、当前网站仓库和已确认选择。只补会影响结果的缺口；一次引导一个动作，不把内部 JSON 或技术参数交给新手填写。

首次可说：“先把这次活动的素材文件夹发来，照片、视频、链接混着放也可以，我先帮你盘点。”读完再用已有材料确认活动名称、日期、地点和案例归属。缺海报时默认用已确认封面；缺合作方 logo、PPT/PDF 时先省略对应位置，不拿示意图冒充真实素材。用户有海报/logo 就引导其发送现有文件，不要求其制作新文件。

本次只检查或改 UI 时，维持范围，不重新整理原素材。多人交接先确认同一活动 UID，不能因目录名或标题变化新增一场活动。

## 归档与持续修订

按 [整理与数据契约](references/archive-contract.md) 工作。首次用 `scripts/archive.py scan` 生成活动外计划；看图片（大图先缩到 1600px 内；批量时做带编号的拼图再逐张对号，避免顺序错位）、抽看视频（ffmpeg 抽 2-3 帧）、打开作品链接后填写分类、中文命名、判断依据和人工选择。相同内容哈希可复用视觉判断；不同案例身份仍独立。不能凭名字或 OCR 代替视觉核验。

`apply` 复制到正式目录，输入原件保留；`mirror` 生成网站展示副本和两份 JSON。先保留历史记录，再更新当前索引。后续用户在正式目录改文件名、排序或素材；只重新处理内容发生变化的文件。改名优先当前目录，旧索引不能还原旧名称；内容替换必须重审。

仅合并字节相同且归属相同的媒体副本或同一案例的相同 URL；同一主题的图片作品、网站、视频分别保留。同名不同作者、不同活动或不同成品不能按标题合并。评分是辅助记录，`首页NN_` 人工顺序优先，未标首页的素材不能靠评分挤进人工首页。

链接要保存来源与归属。作品链接用 `capture_case_links.py` 多时刻取帧，实看后选最能代表玩法/功能的一帧，首屏只有标题、加载或白屏不能当主图；加载页、登录墙、失效链接保留待处理记录。链接清单与案例目录用 `match_case_links.py` 一一对应，歧义不猜。交来的旧整理包、压缩包先用 `absorb_input_packages.py` 比对吸收，已覆盖的重复媒体不再保留。细则和命令见 [链接与输入包](references/links-and-intake.md)。

同一活动分批补素材，或复用以前活动里同一批照片时，`scan` 加 `--archive <已整理活动目录>`：字节相同且只有一个去向的文件直接继承已审核的分类、命名、角色和选中状态，记入 `inheritedFrom`；多个去向列进 `candidates` 待定。`apply` 合并到 `其他/整理记录.json`，保留各批次记录。只改名不会重新压缩。截图进对应案例，原始链接文件保留。源码及内部附件归档，但不自动公开下载。

## 数据生成与预览

按 [执行命令](references/commands.md) 运行 `catalog.py`，将两份 JSON 映射为现有网站 Event 数据，按 UID 只更新目标活动，其他活动保留。显示字段见契约；海报、伙伴 logo、资料是可选扩展。缺城市等事实保持空值，不能为凑版式编造。

新内容的预览使用展示副本；历史线上活动直接读已有完整 catalog。统一详情版式是：左标题简介、右海报/封面；“图片视频”和“案例”两个主分区；资料折叠区；下载是一行小字。图片作品支持组内翻页，网站单独打开，视频按需加载。需要 UI 时修改仓库的 EventDetail/CSS，不改归档协议。

打开本地网页给用户看，确认封面、图片选择、案例对应与文案。用户修订后，更新正式数据，重新生成并检查受影响部分。确认记录绑定当前版本；不能把旧确认套在新增内容上。

## 备份、发布与交接

读 [发布与恢复](references/release.md)。生成发布 catalog（`catalog.py --uploads`）时必须同时带 `--backup` 和 `--evidence`，脚本会先执行备份检查，不通过就不出发布数据。本地可继续整理和预览；对外发布、交接前，确认完整原件与元数据已有云端备份，并明确询问：“这些原件已复制到你的电脑或指定硬盘了吗？请告诉我保存位置。”负责人明确豁免时记录理由，不替其默许。

云端展示压缩图不等于原件备份。完整包必须包含原件、说明、两份 JSON、AI 判断/命名记录；有原站管理数据库和品牌配置时另做一致性备份。云端备份读回校验，网站发布后分别验证页面、媒体和 ZIP 下载。

部署沿用目标环境可用的 `bigapple-deploy` Skill，先读其当前版本；不要内置账号、token、固定服务器目录或另建站点。没有部署能力时保留可交付包并说明阻塞。用户说自己推仓库时，不替其推送，交付提醒其提交并推送当前分支。

旧 Skill 退役：先验证新入口并留存原包；只对用户点名的旧 Skill ID 操作。区分本地入口、市场条目和其他人的副本，分别检查权限。外部删除/替换结果不明先回查，不重复提交。
