# 代码改动说明（前后端分离 + 图片修复）

日期：2026-09-16 ｜ 项目：`anli_web/anli_web`

## 一句话

前端项目里**不放任何图片**：页面上的每张图都靠一个哈希（sha256）对应到云端
（`media.bigapple.app`）那张图；前端只保留代码 + 一个索引文件。

---

## 1 前端为什么可以没有图片

```
素材库（原图真源，项目外，36 GB，只读）
     └─ 网站压缩素材（要上站的那批，项目外，3.6 GB，只读）
              │
              │  scripts/upload-media.mjs  ← 上传到云端，写入云端清单
              ▼
        云端 media.bigapple.app（每张图一个 url）
              │
              │  scripts/build-media-index.mjs ← 按 sha256 精确配对
              ▼
        src/data/mediaIndex.generated.js（前端唯一媒体索引，纯文本）
              │
              ▼
        页面：<img src={item.url}>
```

索引里每条记录 13 个字段，其中 `hash` 和 `url` 是 1:1 对应的：

```js
{
  activityId: '09-05-guangyao',
  path: '01_活动照片/微信图片_20260905125904_846_170.jpg',
  name: '微信图片_20260905125904_846_170.jpg',
  category: '活动',
  rating: '00000',
  isCover: 0,
  onHomePage: 0,
  url: 'https://media.bigapple.app/.../media/<sha256>/<sha256>.jpg',
  hash: '<该文件内容的 sha256>',   // 云端目录名就是这个哈希
  cloudBytes: 774067,
  originBytes: 8955773,
}
```

**配对规则**：本地文件的 sha256 == 云端清单里的 hash → 取那条 url。
对不上就记 `url: ''`，前端不渲染，**绝不拿别的图顶上**。

### 2.1 案例主图修复（`vite.config.js`）

```js
// 改前：只认第一张「主图」，对不上就整条丢掉
const mainImage = images.find((name) => /主图/u.test(path.basename(name)))
  || (images.length === 1 ? images[0] : null);
const relativePath = mainImage ? `02_案例/${folder}/截图/${mainImage}` : null;

// 改后：首选主图 → 对不上就往后找第一张对得上的；全都对不上就不显示
const mainImageCandidates = images.filter((name) => /主图/u.test(path.basename(name)));
if (!mainImageCandidates.length && images.length === 1) mainImageCandidates.push(images[0]);
const relativePath = mainImageCandidates
  .map((name) => `02_案例/${folder}/截图/${name}`)
  .find((candidate) => compressedCaseExists(activityFolder, candidate)) || null;
```

只影响「原本该显示、但因为文件名对不上被丢掉」的条目；不会换图、不会新增别的图。

## 3 以后怎么加图 / 传图

```bash
# 1. 把要上站的图放进项目外的「网站压缩素材/<活动目录>/」（长边 2000px，约 300–600 KB）
# 2. 上传到云端（已上传过的会自动跳过，改了文件会重新传）
node scripts/upload-media.mjs \
  --media-root "/Users/Admin/Desktop/anli_web_图片存档/网站压缩素材" \
  --folders "2026-09-05-光耀基金会活动"

# 先看会传什么、不写云端：
node scripts/upload-media.mjs --media-root ... --folders "..." --dry-run

# 3. 重新生成索引
node scripts/build-media-index.mjs

# 4. 重新构建
npm run build
```

上传脚本要点：

- 用 sha256 当对象名：`media/<sha256>/<sha256>.jpg` —— 同一张图重复上传不会产生副本。
- 活动 id 从 `src/data/mediaIndex.generated.js` 的「目录名 → 活动 id」反查，
  所以「…活动」和「…活动一期」这种目录名分叉也能认领。
- 只读本地图片，只写云端清单 `src/data/publicMediaMap.generated.js`。

### 3.1 补齐「本地有、云端没有」的图

比 `upload-media.mjs` 更省事：直接把索引里 `url` 为空的条目当作待办清单。

```bash
node scripts/upload-missing-media.mjs --dry-run   # 先看要传什么、多大
node scripts/upload-missing-media.mjs             # 传图片（默认不含视频）
node scripts/upload-missing-media.mjs --only 09-06-duibai-sharing
```

它做了三件事：活动 id → 归档目录名归一化匹配、sha256 幂等跳过、
按 `--max-bytes` 预算上传并在额度不足时安全停下（已传部分保留）。

### 3.2 云端额度（实测）

| 限制 | 触发时的返回 |
|---|---|
| 单个对象 ≤ 128 MB | `413 {"error":"对象超过 128MB 限制"}` |
| 单个应用总容量 ≤ 128 MB | `413 {"error":"应用存储额度不足：当前 130962KB，请求 509KB，上限 128MB"}` |
| **一个 publisher 跨应用合计 ≤ 256 MB** | 同上；2026-09-16 新建第二个应用 `bigapple-events-media` 后实测确认 |

额度以 `bigapple-deploy` Skill 的 `## Resource limits` 为准。`upload-missing-media.mjs` 支持 `--app <appId>` 指定传到哪个应用；索引里存的是绝对地址，所以前端无感。

本机凭据只能写自己账号下的应用（`bigapple-onboarding-course`），
平台媒体库应用（3000+ 张图所在）既读不到也写不进。
批量上传前先 `--dry-run`；不够就得先扩额度或提供媒体库应用的凭据。
