**页面上没有任何空白图片。** 全站逐页实测（首页、档案页、34 个活动详情页、
34 个相册页、34 个案例相册页）：

第一次扫描时出现的「空白」是**误报**：那是图片还没下载完（`complete = false`），
等久一点全部加载成功（例如 `06-28-6` 相册：先挂起 95 张，最终 166/166 全部显示）。

**真正缺的不是空白，是「本地有图、云端没有」的图。** 这些图按硬规则不渲染，
所以页面上不会留白框，只是内容少了一些。本次就是把这些能补的补上。

## 三、还差什么，为什么没补上

云端额度被精确测出来了（服务端原话）：

```
413 {"error":"应用存储额度不足：当前 130962KB，请求 509KB，上限 128MB"}
```

- 单个应用总容量 **128 MB**，现在已用 **130.9 MB**（满了）。
- 另外单个对象上限也是 128 MB：`413 {"error":"对象超过 128MB 限制"}`。
- 平台自己的媒体库应用（3000+ 张图所在，`pub_e06ae57c-…/apps/media`）
  不归本机凭据所属账号，**既读不到清单也写不进去**，所以不能借用它的空间。

剩余 274 条没链接的，全部卡在这个额度上：

| 类别 | 数量 | 体积 | 说明 |
|---|---|---|---|
| 图片 | 166 | 约 90 MB | 对白分享会 133 + `01-1` 源码目录副本 22 + activity-24 3 + activity-29 3 + activity-30 2 + activity-25 1 + guangming 1 |
| 视频 | 108 | 约 1.5 GB | 08-16-ai-16 40、activity-27 18、08-27-20 15、activity-24 7、08-26-fde-19 7、07-bnijeff-13 6、其它 15 |

**扩额度之后**，两条命令即可补齐（脚本幂等，已传的会跳过）：

```bash
node scripts/upload-missing-media.mjs                     # 补 166 张图
node scripts/upload-missing-media.mjs --include-videos    # 连 1.5 GB 视频一起补
node scripts/build-media-index.mjs && npm run build
```

## 四、视频为什么改成不渲染

108 个视频在页面上是**空播放器**（`<source src="">`），这是**旧版 9/9 构建就有**的问题
（实测旧版 08-16-ai-16 相册：40 个视频全空）。视频总量 1.5 GB，额度不可能装下，
所以前端改为「没有云端链接的视频不渲染」——和图片同一条硬规则，空白播放器消失。

## 八、四个地方分别存了什么、多大（最容易混的一笔账）

网站打开时用的是「云端」的图，但云端的图分在两个不同的应用里，另外你电脑上还有三份存档：

| # | 位置 | 装什么 | 有多少 | 谁能写 |
|---|---|---|---|---|
| ① | **平台媒体库**（`pub_e06ae57c-…/apps/media`） | 网站原来的图，3139 条 | **约 1.94 GB** | 平台自己。本机凭据**读不到也写不进** |
| ② | **我们账号的应用**（2 个：`bigapple-onboarding-course` + `bigapple-events-media`） | 今天补的图，386 个对象 | **177.9 MB / 账号合计上限 256 MB** | 本机凭据可写 |
| ③ | 本机 `素材库` | 原图真源 | **36 GB** | 只读不改 |
| ④ | 本机 `anli_web_图片存档` | 网站压缩素材 3.6 GB + src_assets_events 2.2 GB + 过程产物 480 MB | **约 6.3 GB** | 归档，不要删 |

**前端项目本身：0 张图片文件**，构建产物就是一个 `dist/index.html`（3.4 MB，内联图只有 1 张 4.5 KB 的 logo）。

所以「满了」指的是 ②（128 MB 的小桶），不是 ①（1.94 GB 的媒体库），也不是你电脑上的 36 GB。
今天补的 248 张图之所以只能塞进 ②，是因为 ① 不归本机凭据所属账号，写不进去。
