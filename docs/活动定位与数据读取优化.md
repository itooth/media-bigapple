# 活动定位与数据读取优化

日期：2026-11-13。仅本地实现、测试和预览；未推送、未部署、未更改生产数据或图床。

## 行为变化

1. 活动详情内“查看案例”“图片视频”“回到顶部”直接定位到原锚点，不再平滑滚过长照片墙。链接锚点与修改键点击保留，照片在上、案例在下，布局和样式没有改变。
2. 首页请求 `/api/site?view=catalog`，仅返回活动卡片与既有活动/案例搜索需要的字段；详情请求 `/api/site?event=<slug 或旧标识>`，仅返回当前场活动。单场详情、现场相册和作品相册之间复用同一响应。
3. 中文旧链接切换为规范短链接时复用已取得的数据。切换活动时取消旧请求，迟到响应不会覆盖当前页面；请求失败可重试。目录与详情间切换保留搜索界面状态。
4. 数据仍从现有 SQLite 内容源读取，保留 `no-store` 与原保存流程。保存、追加、删除或代理商选场变更后，下一次读取立即使用当前内容，无需重新构建网站。未新增定时刷新或推送机制，已经打开的页面仍按原有方式通过重新进入/刷新取得更新。

## 兼容范围

- 无查询参数的 `/api/site`、`/api/sites/<id>` 保留原完整返回，现有调用方不受影响。
- 代理商先按选定活动过滤，再查找单场；即使不同活动共用历史 id，也不会跨越品牌选场范围。
- 代理商 gateway 只透传 `view=catalog` 或 `event` 查询参数，代理商编号继续固定在配置中，不转发用户凭证。
- 未更新的旧 gateway 会忽略查询参数、返回其原有范围的完整数据，新前端仍可使用；以后上线时需要一并更新 gateway，代理商入口才能获得相同的数据量改善。本轮未发布任何 gateway。
- 未增加缓存存储、修改数据库结构、重命名或搬迁素材，也未覆盖本地种子与生产活动的差异。

## 数据量与定位对照

基于同一份 48 场公开快照，gzip 正文字节：

| 读取对象 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首页目录 | 444,934 B | 61,000 B |
| 直接打开第十二期详情 | 444,934 B | 34,961 B |

详情数据体积约减少 92%，首页约减少 86%；这不等于真实网络下页面耗时按同比例缩短。

第十二期从首屏定位到案例：修复后新增 5 条图片资源记录，上方已加载现场照片保持 9 张。此前线上平滑滚动对照新增 477 条资源记录，已加载照片 9 → 480。资源记录可能包含缓存读取，不能等同于回源次数。
